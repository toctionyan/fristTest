- `TurnSemanticContract`, typed Goals, Plans, ResultRefs, transaction Draft/Grant/Attempt/Receipt, and RuntimeOutcome projections must keep one explicit authority each.
- Do not add keyword routing, silent legacy fallback, duplicate semantic owners, or test-only runtime branches.

- Changes must identify the exact runtime owner and run focused, counterexample, negative-path, and complete standard regression evidence.
- Product implementers may not edit Skill governance, Quality Targets, Claims, Judge logic, attestations, or closure evidence.
