# Anti-Stall acceptance status

This branch keeps Quality Loop gate, claim, repair-round and convergence semantics unchanged while adding a separate remote-input acquisition harness plus exact same-run checkpoint resume.

## B1 — Anti-Stall execution acceptance

B1 is acceptable only when focused regressions prove all of the following:

- frozen working-set deduplication avoids duplicate remote reads;
- immutable snapshot cache hits consume zero remote calls and a changed ref forces refresh;
- independent misses execute in bounded batches with maximum width 4;
- one primary timeout/503/empty-result opens its circuit and permits at most one declared fallback;
- fallback failure stops that resource without a third remote path;
- concurrent cache writes preserve every cache index entry;
- process-control exceptions are not swallowed by remote failure handling;
- performance metrics report physical remote reads separately from serial remote depth;
- the anti-stall harness does not own or redefine Quality Loop gate/claim/convergence decisions.

Focused Anti-Stall regression entry point:

`skill-system/tests/test_anti_stall_controller.py`

## B2 — Resume acceptance

Controller-level and CLI-level regressions cover exact same-run resume, completed-evidence fingerprint validation, source-snapshot drift rejection, owned-checkpoint cleanup, automatic interrupted evidence selection when `--evidence-dir` is omitted, and intentional fresh execution when a new evidence directory is supplied explicitly.

Focused Resume regression entry points:

- `skill-system/tests/test_quality_loop_resume_integration.py`
- `skill-system/tests/test_quality_loop_resume_cli.py`
- `services/agent-service/tests/runtime/test_quality_loop_checkpoint.py`

Existing baseline, repair-round and targeted `rerun-from` behavior remain under the standard Quality Loop controller suite rather than a new parallel loop.

## B3 — Portable adoption boundary

The shared `product-code-governance` Skill declares Anti-Stall as a `WORKFLOW_DEFAULT` for the current environment, Codex and Claude Code. The executable defaults are bound by regression to `max_remote_calls = 2` and `max_parallel <= 4`.

Repository code cannot intercept ChatGPT platform-level GitHub Connector calls. In that host, the same Working Set / Budget / Circuit / bounded-fallback discipline must be applied by the task executor; this branch does not claim platform interception.

## B4 — Lean implementation review

The pre-merge review removed unused future-facing abstraction instead of preserving it for hypothetical callers:

- Working Set now owns only declaration, freeze and deduplication; duplicate `remote_plan` representation and unused item role metadata were removed.
- Batch planning now owns only deterministic source/ref grouping and the hard parallel cap; the unused dependency-DAG layer was removed because the real harness had no dependency input.
- Fallback state now owns only primary/fallback remote-attempt transitions; cache and local-analysis states remain with `SnapshotCache` and `AntiStallTaskHarness`.
- Anti-Stall tests moved out of `services/agent-service/tests/runtime` into `skill-system/tests`, so control-plane changes no longer perturb the protected product-source baseline.
- Python bytecode artifacts generated by validation are removed, and `.gitignore` now rejects `__pycache__/` and `*.py[cod]`.

Compared with the pre-slim B3 head, the PR changed-file count fell from 23 to 17 and total additions fell from 2910 to 2415 while retaining the B1/B2/B3 behavior contracts.
