# Architecture Decision Contract

架构类变更必须至少比较：

1. 保守方案：沿用现有结构；
2. 演进方案：保留硬边界，替换局部实现；
3. 重构方案：采用更优职责模型并给出迁移路径。

每个方案比较：正确性、权威边界、概念数量、依赖变化、迁移成本、回滚成本、验证成本和长期扩展成本。

最终决策必须说明：

- 为什么选中；
- 为什么没有选择更简单方案；
- 选择的是哪些职责边界，而不是只列类名；
- 保留哪些硬不变量；
- 删除或退休哪些旧抽象和正式读写路径；
- Cutover、回滚和清理策略；
- 哪些规则只是默认而非硬不变量；
- 哪些行为 Claim 和反例决定成功；
- 哪些未知仍未验证；
- 是否需要改变当前 Project Baseline。
