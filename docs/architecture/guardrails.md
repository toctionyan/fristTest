# 当前架构红线

1. 所有聊天、UI 授权、补充输入、提交和恢复必须经唯一正式 Lifecycle。
2. Runtime 不自动解释代词、不自动换对象、不以相近能力替代缺失能力。
3. 写操作必须保留 Draft → Grant → Attempt → Receipt / Reconcile。
4. Core 不得持有订单、退款、物流、工单等领域默认实现。
5. 新能力以模块垂直闭环安装；不得扩张万能 `capability/action` 枚举。
6. 模块内部不能以 shared facade 重新长成总调度文件。
7. 当前工作区不得携带历史交付、正式不可达兼容链、缓存、数据库、日志或上传文件。
8. 目录、治理配置、发布证据和运行数据边界由 V5 统一架构验收器强制验证。
